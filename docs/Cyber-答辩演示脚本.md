# Cyber 攻防演示 · 答辩脚本

> 配套任务线:9 项攻防优化任务(T1-T9)全部完成,本脚本给出从"系统介绍"到"多轮对抗演示"再到"交付物导出"的完整答辩路线。
> 每步标注:操作动作 / 讲解话术要点 / 对应的比赛评分点。建议演示总时长 5-8 分钟(可压缩为 3 分钟精华版)。

---

## 0. 演示前准备(3 分钟,不占用答辩时间)

| 项目 | 操作 | 检查点 |
|---|---|---|
| 后端启动 | `python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000` | 日志出现 `AegisOS backend started` |
| 前端启动 | `cd frontend && npm run dev` | 浏览器打开 http://localhost:5173 |
| 系统模式 | 顶栏确认 mode(建议演示开场用 **real**,失败自动降级 mock) | 有 LLM Key 时显示 `deepseek` |
| 预跑数据 | 可选:提前用 mock 跑 1 次 3 轮演练 | 历史演练区有 ≥3 条记录,趋势图/闭环图素材就位 |

> 应急:若真实 LLM 不可用(无 Key/超时),在系统设置把 mode 切到 `mock`——**所有演示功能在 mock 下同样完整**,仅 LLM 生成内容为模拟。答辩时可直接说明"为演示稳定性使用内置模拟,真实模式下同一套流程调用大模型"。

## 1. 开场定调(30 秒)

**操作**:停在系统总览页(Cyber 主入口)。

**话术**:
> "我们构建的是一个端-边-云协同的多智能体攻防推演系统:红队负责攻击、蓝队负责防御、紫队负责评审,三轮对抗证据驱动收敛,并且全程可观测、可导出、可对比。"

**评分点**:总分结构开场,交代"多智能体 + 端边云 + 证据驱动收敛"三大关键词。

---

## 2. 红队攻击链:推理可见(1 分钟)

**操作**:Red Team 标签 → **Run Attack**(建议 real 模式,失败降 mock)。

**讲解要点**(按画面顺序):
1. **资产节点彩色区分**:🖥 Web(绿)/ 🗄 数据库(蓝)/ ⚡ 缓存(橙)/ 🖧 服务器(紫)——"红队先做侦察,按暴露服务对资产分类"。
2. **漏洞徽章配色**:节点下方 cvss 分值色块(≥9 红 / 7-9 橙 / 4-7 黄)——"漏洞按严重度着色,9.8 分的高危漏洞一目了然"。
3. **攻击链连线 + 编号徽章**:①②③ 顺序箭头 + 技法编号——"攻击链从公网入口横向移动到内网,每步标出 ATT&CK 技法"。
4. **步骤下方推理卡片**:"为什么这么打"——"这一步选暴力破解,因为目标暴露登录接口且无锁定策略;选它作为突破口成本最低"。

**评分点**:能力维度 e(中间决策轨迹)+ 应用创新(视觉呈现)。

---

## 3. 蓝队防御:渐进展示 + 量化指标(1 分钟)

**操作**:Blue Defense 标签 → 执行一次蓝队分析(或从演练轮次卡片展开蓝队块)。

**讲解要点**:
1. **四阶段渐进展示**:检测 → 分诊 → 狩猎 → 响应,逐步出结果,不干等——"蓝队按阶段推进,每一步都能看到中间产物"。
2. **覆盖率 + 安全评分**:展开蓝队响应后显示"防御覆盖率 X%(N 技法 vs M 检测技法)+ 安全评分"——"覆盖率量化了检测对攻击技法的覆盖程度,是蓝队效果的客观指标"。

**评分点**:体验(渐进式反馈)+ 效率(量化指标)。

---

## 4. Auto Drill 多轮对抗:收敛证据链(2 分钟,核心)

**操作**:Auto Drill → Start Drill(mock 3 轮,约 10-20 秒;real 模式约 1-3 分钟)→ 跑完后依次指:

### 4.1 收敛趋势图(技术 20 分主图)
> "三条曲线:红队新增攻击步骤(红)、蓝队响应动作(蓝)、防御覆盖率(绿)。看数据:第 1 轮新增 2 个攻击步骤,紫队判定不合格、挑出缺口;第 2 轮红队补攻 1 步,紫队判定通过;第 3 轮红队**无新招可出**——对抗升温后收敛,这就是证据驱动收敛。"

### 4.2 缺口闭环图(完整性 40 分)
> "跨轮闭环:第 1 轮紫队指出'攻击链未覆盖高价值资产 asset-4';第 2 轮红队立刻补上 T1078 攻击直达 asset-4;紫队复核通过。挑缺口 → 补攻击 → 判定通过,闭环完整。"

### 4.3 展开轮次卡片看执行位置(维度 c 核心)
> "每轮红/蓝/紫都有执行位置标注:第 1 轮红队端侧(超低延迟)、蓝队边侧、紫队云侧(高算力);第 2 轮紫队负载下降,从云侧卸载到边侧——端边云自适应调度真实运行。"

**评分点**:技术 20(收敛算法)+ 完整性 40(感知-规划-执行-反馈闭环)+ 能力维度 c(端边云调度)。

---

## 5. 战报导出:交付物直接生成(30 秒)

**操作**:跑完演练后点 **📄 运行记录报告** → **🖨 导出 PDF** → 打印对话框选"另存为 PDF"。

**话术**:
> "整场演练的完整战报——每轮红/蓝/紫产物、端边云卸载轨迹、收敛总结——一键导出为 PDF,直接作为交付材料。材料文档 + 可运行系统双轨交付。"

**评分点**:交付物完整性(材料文档)。

---

## 6. 历史演练对比:多任务复用(30 秒)

**操作**:页面底部「🕘 历史演练」→ 勾选两条收敛码不同的记录(如一条 `converged`、一条 `max_rounds`)。

**话术**:
> "系统已经跑过大量演练,全部落盘可查。选两条对比:这条证据驱动收敛、那条触顶轮次上限,指标表和收敛趋势并排展示——同一系统、不同场景,可复用、可对比。"

**评分点**:完整性 40(多任务场景演示)。

---

## 7. 收尾总结(30 秒)

**话术**:

## 附:常见突发处理

| 突发 | 处理 |
|---|---|
| 真实 LLM 超时/失败 | 顶栏切 mock,重跑;话术:"演示环境限流,切内置模拟保证演示完整" |
| 趋势图/闭环图没出现 | 需 ≥2 轮才有;若只跑了 1 轮,继续跑或改用历史演练对比 |
| 导出 PDF 弹窗被拦截 | 浏览器允许弹出窗口;或提示评委"保存为 PDF 后即交付材料" |
| 前端 5173 起不来 | 检查 node_modules;`npm install` 后重试 |
| 端口 8000 被占用 | 结束占用进程后重启 uvicorn |

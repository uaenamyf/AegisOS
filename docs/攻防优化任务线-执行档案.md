## 0. 使用规则(每次开工前必读)

### 0.1 每轮循环工作流(与 CyberDrill 档案一致)

1. **开工前(必做)**:回到本文档对应任务小节,把「设计档案」讲给用户 5 件事:
   ① 要交付什么(新增/改造哪个**模块**、提供什么能力,讲实际逻辑不讲代码名)
   ② 对应比赛什么要求(能力维度/评分点)
   ③ 与其他模块的联系(后端哪个功能模块、前端哪个可见按钮/面板)
   ④ 模块内部逻辑(流程/数据从哪来到哪去/技术机制)
   ⑤ 验收标准与实测位置(前端哪里看得到)。
   **等用户确认后才动手。**
2. **开工**:严格按该任务「交付产物」实现;尽量小步、可回退。
3. **开工后(必做)**:填写该任务「开工后记录」:交付了什么、改动体现在项目哪里(前端哪里可见/内部调用链)、测试结果、git 提交、实测结果、遗留问题。
4. **git 提交**:每轮至少一次提交,提交说明只写产品变更与验证;本轮结束前工作区必须干净,以提交点作为回退锚点。
5. **版本回退同步**:若因任何原因回退到某轮,**本文档必须同步回退到该轮「开工后记录」完成时的状态**;代码有新更新,本文档跟随更新。**文档与代码永远在同一版本。**

## 1. 现状盘点(开干前先知道有什么)

### 1.1 已经能做什么(Phase 0-5 成果 + 最近一轮优化)

- **一键多轮攻防演练**:点「开始演练」→ 红队扫描资产/找漏洞/规划攻击链 → 蓝队收到攻击事件流出告警/假设/响应计划 → 紫队评审挑缺口 → 红队带反馈继续 → 收敛提前收工 → 弹出总结报告。支持 mock/真实大模型两种运行方式,顶部徽标一键切换。
- **逐 agent 输入输出追踪**:每个 agent(红队 3 个、蓝队 4 个、紫队 2 个)的输入提示词和结构化输出,后端已记录并在前端红/蓝/紫三面板底部可展开查看;演练每轮战报也含追踪记录。
- **中断恢复**:单链面板结果存浏览器本地,刷新/切页不丢;演练面板存会话快照,断线自动补拉。
- **停止立即生效**:点停止后,演练在当前 agent 调用边界快速退出,不再等整轮跑完。
- **单链可视化**:红队攻击链流程图(资产→漏洞→步骤连线)、蓝队告警/动作分布条、紫队时间线回放、威胁情报搜索。

### 1.2 已有的数据基础(后续任务直接用的"原材料")

- 演练每轮战报已包含:红队资产/漏洞/攻击步骤(含新增标记)、蓝队告警/假设/动作、紫队判定(合格/不合格)与问题列表、**每阶段执行位置标注(端/边/云,含原因说明)**、收敛码。
- 单链结果已包含:agent 追踪、执行耗时。
- 以上数据前端**大部分已经收到**,只是还没有对应的可视化组件——所以 T3/T4/T5/T6 这类"纯前端展示"任务成本低、见效快。

## 2. 任务设计档案(每个任务开工前必读)

### T1 蓝队渐进展示(四阶段逐步出结果)

- **要交付什么**:蓝队面板从"点执行后干等 40-60 秒、一次性出全部结果"改成"四阶段逐步出结果"——检测中 → 分诊中 → 狩猎中 → 规划中,每完成一个阶段立刻在屏幕上显示该阶段产出(先出告警,再出分类,再出假设,最后出响应计划)。真实大模型模式下体验从"等待"变成"观看推理过程"。
- **对应比赛什么要求**:应用创新 25 分里的"用户体验 5";能力维度 e"展示中间决策过程"——蓝队每步推理过程逐步呈现,本身就是推理轨迹展示。
- **与其他模块的联系**:红队面板已经有同样的流式体验(三阶段逐步出结果),蓝队是补齐体验短板;后端各 agent 本来就是分步执行的,只是目前一次性返回,需要把"分步"传到前端。
- **模块内部逻辑**:后端新增一条蓝队流式通道,按检测→分诊→狩猎→规划四个阶段依次推送结果片段;前端蓝队面板订阅该通道,收到哪段就渲染哪段,全部收完后汇总成完整结果并存缓存。
- **验收标准**:真实模式下点执行,屏幕上四阶段依次出现,每阶段有阶段名与产出;结束后结果与一次性返回完全一致;mock 模式秒出不受影响。
- **实测位置**:Cyber 页面 → 蓝队面板 → 输入事件流 → 点执行(切到真实模式看效果)。
- **注意事项**:失败兜底(某阶段出错不中断整体);与现有缓存/追踪/分布条功能共存。

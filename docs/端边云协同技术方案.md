## 1. 工程取舍：我们理解的"模型切分"

赛题 C-4 要求"与模型切分"。工业界对此有两种主流解读：

| 方案 | 做法 | 是否需要 | 我们的结论 |
|------|------|:--:|------|
| **层间切分 (split inference)** | 把单个模型的前若干层放在端侧、后若干层放在云侧，靠高速互联协同推理 | 需同族模型 + 极高速互联（如 5G/专线）+ 模型结构深度配合 | ❌ 我们的异构三层（0.5B/7B/API）不是同一族模型，做不了也不必要 |
| **任务级切分** | 把一次重推理拆成多段轻计算，分布到不同层级执行 | 普适，适配异构算力 | ✅ **我们采用的方案** |

选择任务级切分的社会论证：
- 赛题强调"**异构**算力"——异构正是任务级切分的主场（不同层级擅长不同任务）；
- 层间切分违背"异构"前提，反而要求打通模型内部结构；
- 任务级切分更贴近真实工业落地（近端优先、敏感数据本地化、按需升级）。

> 这个工程取舍本身就是技术创新性的论证点：我们明确识别了赛题概念的歧义，并做出了与业务约束自洽的选择。

## 2. 算法一：级联推理（Cascade Inference）

### 2.1 思想

**类比公园分级诊疗**——不是所有问题都直接上顶级专家：
1. 简单问题先用**廉价模型**（端侧 0.5B）：快、免费、数据不出本机；
2. 模型输出**置信度不足**时，才升级到更强的模型（边侧 7B）；
3. 仍不足才调用**大模型 API**（云侧最强、最贵、最慢）。

**直接收益**：简单问题不再浪费昂贵模型 token → 对标评分表"资源效率（token 与时间）5 分"。

### 2.2 置信度启发式（零额外 token）

升级判断不需要再调用模型，纯规则评估输出质量（O(1)）：

| 因子 | 规则 | 作用 |
|------|------|------|
| 成功性 | `ok=False` → 0.0 | 失败必升级 |
| 长度 | 过短（<30字符）→ 低分 | 截断/无意义 |
| 重复字符 | 高占比 → 降分 | 模型退化/复读机 |
| 长度饱和 | 越长 → 越接近 0.85 | 充分回答 |

### 2.3 伪代码

```
输入: 任务 task, 提示词 prompt, 策略 policy
输出: 结果 result（含每跳轨迹）

def run_cascade(dispatcher, task, prompt, policy):
    chain = policy.hop_chain or ["device", "edge", "cloud"]
    max_hops = min(policy.max_hops, len(chain))
    hops = []

    for hop_idx in range(max_hops):
        tier = chain[hop_idx]
        task.latency_budget = 映射到该层级的预算   # 让调度器天然选中目标层
        result = dispatcher.dispatch(task, prompt)
        conf = assess_confidence(result)            # 零 token 启发式
        hops.append({hop, tier, result.tier, conf, latency})

        if result.ok and conf >= policy.threshold:
            result.attempts = hops
            return result                            # 够好，不升级（省 token）

    return hops 的最后一跳结果                      # 不自信，返回最优可得
```

### 2.4 复杂性分析

- **时间复杂度**：O(max_hops) 次推理。每跳调度 O(n)（n=在线节点数），置信度评估 O(L)（L=输出长度）。
  总计 O(max_hops · (n + L))，且 max_hops ≤ 3 为常数。
- **token 效率**：设满级直接上云需 T 个 completion token；级联在端侧/边侧就自信解决时，
  高跳 token = 0。**期望 token 消耗从 T 降到 p·T**（p = 需要升级的比例，简单问题 p 很小）。
- **空间复杂度**：O(max_hops) 轨迹存储，可忽略。

## 3. 算法二：分段流水线（Segment Pipeline）

### 3.1 适用场景

**长文档安全分析**（如 10 万字符的日志/告警全集）。若整体上云：① 超出上下文窗口；② 敏感信息全量暴露给第三方 API。

### 3.2 三段式

```
端侧 device   分块 chunk + 敏感脱敏（复用 R7 正则）
              → 把每条带敏感标记的块原地脱敏
边侧 edge     中间块局部摘要（块级）
              → 只升级脱敏后的摘要块
云侧 cloud    全局综合（只看脱敏摘要，不见原始敏感数据）
              → 输出全局攻击链/结论
```

**关键收益**：云侧只见脱敏摘要 → 敏感数据物理隔离在端边；全局综合在云 → 算力充分。

### 3.3 伪代码

```
输入: 长文档 text, 隐私分类器 classify, 分块大小 k
输出: 全局综合结论

def segment_pipeline(dispatcher, task, text, k):
    # 1. 端侧：分块 + 脱敏
    chunks = [text[i : i+k] for i in range(0, len(text), k)]
    for i, c in enumerate(chunks):
        if classify(c) 判别为敏感:
            chunks[i] = redact(c)          # 替换敏感字段（IP/密钥/CVE→占位符）

    # 2. 边侧：块级摘要（可选，仅对敏感块做）
    summaries = []
    for c in chunks:
        local = dispatcher(edge, "摘要: " + c)
        summaries.append(local)

    # 3. 云侧：全局综合（只看脱敏摘要）
    synthesis_prompt = "综合以下各段摘要，生成全局结论: " + join(summaries)
    return dispatcher(cloud, synthesis_prompt)

def redact(text):
    for pattern in 强敏感规则:               # 复用 R7 privacy_classifier
        text = pattern.sub("<REDACTED>", text)
    return text
```

### 3.4 复杂性分析

- 分块：O(n)（n=文本长度，纯字符串切片）。
- 摘要：O(n/k) 次边侧推理（k=块大小），每次 O(k) → 边侧总计算 O(n)。
- 通信量：全量上云为 O(n)；分段后边→云只传 O(n/k) 条摘要（每条固定长），
  通信量**从 O(n) 降到 O(n/k) + k**（k 为常数块头）——数量级下降。
- 空间：O(n/k) 摘要存储，远小于原始 O(n)。

### 3.5 为何安全

| 数据 | 停留位置 | 是否上云 |
|------|---------|:--:|
| 原始敏感字段（IP/凭据/CVE代码） | 端侧（脱敏后） | ❌ |
| 脱敏后的块摘要 | 边→云 | ✅（已无敏感字段） |
| 全局综合结果 | 云 | ✅（纯分析结论） |

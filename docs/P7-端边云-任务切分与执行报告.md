### 1.1 真实硬件约束（团队实际情况，任务设计的前提）

| 层级 | 实际载体 | 接入方式 |
|------|----------|----------|
| 端 device | 本地开发电脑跑小模型 | 本机 Ollama（`http://localhost:11434`），如 qwen2.5:0.5b/1.5b |
| 边缘 edge | 一台云服务器/实验室服务器 | 服务器上跑 Ollama 中型模型或轻量 FastAPI 边缘服务，HTTP 可达 |
| 云 cloud | 商用大模型 API | OpenAI 兼容 ChatCompletions（现有 `sdk_provider.py` 已支持火山 ARK） |

# R2 —— 端侧节点运行时（本地 Ollama 小模型）

## 开工前报告（详细版）

### A. 要做什么（精确到接口签名与文件）

**A1. 统一推理结果契约**（追加到 `infrastructure/nodes/descriptor.py`，全任务线贯穿 R4-R12）：

```python
class InferenceResult(BaseModel):
    """一次跨层推理的统一返回。"""
    ok: bool = True            # False 时 text 为空、error 有值，绝不抛异常
    text: str = ""             # 模型输出文本
    node_id: str = ""          # 执行节点（如 device_local）
    tier: str = ""             # device | edge | cloud
    model_id: str = ""         # 实际模型
    latency_ms: float = 0.0    # 端到端耗时（含网络）
    usage: dict = Field(default_factory=dict)   # {"prompt_tokens": int, "completion_tokens": int}
    error: str = ""            # 失败原因（连接拒绝/超时/HTTP错误码）
```

**A2. 端侧节点类** `infrastructure/nodes/device/device_node.py`：

```python
class DeviceNode:
    def __init__(self, profile: NodeProfile) -> None          # 持有 R1 档案，不重复配置
    def health(self) -> bool                                   # GET base_url/api/tags 200 即在线
    def infer(self, prompt: str, *, system: str = "",
              temperature: float = 0.7, max_tokens: int = 512,
              timeout_s: float | None = None) -> InferenceResult  # None→profile.timeout_s
```

- 底层协议：Ollama REST `POST {base_url}/api/generate`，请求体
  `{"model": model_id, "prompt": prompt, "system": system, "stream": false,
    "options": {"temperature": t, "num_predict": max_tokens}}`；
  响应取 `response`（文本）、`prompt_eval_count`/`eval_count`（token 数）、`total_duration`。
- HTTP 客户端：标准库 `urllib.request`（超时参数原生支持），零新依赖。
- 失败语义：`URLError/timeout/HTTPError` 全部捕获 → 返回 `ok=False, error=...`。

### B. 对应比赛什么要求

- C-1"适配终端异构算力环境"的实体化：本地小模型=赛题中的终端算力；privacy=local 子任务的物理隔离保证（数据不出网卡）。
- 联动评分表"系统兼容性"：任何装了 Ollama 的电脑即可成为端侧节点，演示时可现场拉起。

### C. 和其它模块有什么联系

| 方向 | 模块 | 关系 |
|------|------|------|
| 输入 | R1 NodeProfile | DeviceNode 由档案实例化，base_url/model_id/capabilities 全部来自 infrastructure.yaml |
| 输出 | R6 Dispatcher | dispatcher 按 tier==device 寻址本类；health() 供 R5 心跳轮询 |
| 不碰 | aegisos_agents/tools/llms/ | 那是 Agent SDK 推理通路；DeviceNode 是基础设施域旁路推理通路，二者在 R6 汇合（遵守 infrastructure/AGENT.md 禁改业务逻辑约束） |
| 测试 | tests/infrastructure/nodes/ | 与 test_descriptor.py 同目录并列 |

### D. 内部逻辑（数据流）

```
infer(prompt)
  → 组装 payload（model/prompt/system/stream=false/options）
  → urllib.request.urlopen(POST /api/generate, timeout)
  → json.loads(resp)
  → InferenceResult(text=response, latency_ms=计时, usage={prompt_eval_count, eval_count})
异常分支 → InferenceResult(ok=False, error=repr)
```

无会话状态、单请求幂等；不缓存（端侧本地调用无网络成本，缓存留给 edge）。

**A1. 边侧节点类** `infrastructure/nodes/edge/edge_node.py`：

```python
class EdgeNode(BaseHttpNode):
    """边侧节点：区域级推理与数据汇聚。

    支持两种 provider（由 NodeProfile.provider 决定路由分支）：
      - ollama：服务器也跑 Ollama 中型模型，复用与 DeviceNode 完全相同的
        POST /api/generate REST 协议（仅 base_url/model_id 不同）；
      - aegis_edge：服务器跑我们自带的极简边缘服务（A2），协议为
        POST /infer（JSON: prompt/system/max_tokens → InferenceResult JSON）
        + GET /health。
    无论服务器条件如何（装了 Ollama 或仅跑我们的零依赖脚本），都能接入。
    """

    def __init__(self, profile: NodeProfile) -> None          # tier==edge 守卫
    def health(self, timeout_s: float = 3.0) -> bool           # provider 分支：ollama→GET /api/tags；aegis_edge→GET /health
    def infer(self, prompt: str, *, system: str = "",
              temperature: float = 0.7, max_tokens: int = 512,
              timeout_s: float | None = None) -> InferenceResult  # provider 分支路由
```

继承 R2 已有的 `BaseHttpNode`（`infrastructure/nodes/base.py`），复用 `_post_json / _get_json / _timed_infer / _describe_error / _result`——**零新底层代码**，差异仅在 `health()` 和 `infer()` 内的 provider 分支与 URL 拼装。

**A2. 自带极简边缘服务** `tooling/scripts/edge_server.py`（约 100 行，零依赖 stdlib `http.server`）：

```
GET  /health          → {"status":"ok","model":"<name>","cache_size":N}
```

### D. 内部逻辑（数据流）

```
EdgeNode.infer(prompt)
  ├─ provider == "ollama"
  │   → 组装 Ollama payload（model/prompt/system/stream=false/options）
  │   → _post_json("/api/generate", payload, timeout)
  │   → InferenceResult(text=response, usage={prompt_eval_count, eval_count})
  │
  └─ provider == "aegis_edge"
      → 组装 aegis_edge payload（prompt/system/max_tokens）
      → _post_json("/infer", payload, timeout)
      → InferenceResult 直接从响应 JSON 映射（ok/text/usage/latency_ms）

异常分支（两路共用 BaseHttpNode._timed_infer）
  → _describe_error(exc) → InferenceResult.failure(error=...)
```

EdgeNode.health() 同理按 provider 分支选 URL。
无会话状态、单请求幂等；aegis_edge 的缓存放在 edge_server 侧而非 EdgeNode 客户端侧（缓存是边缘服务器的职责，客户端不缓存）。

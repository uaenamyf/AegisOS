### 1.1 真实硬件约束（团队实际情况，任务设计的前提）

| 层级 | 实际载体 | 接入方式 |
|------|----------|----------|
| 端 device | 本地开发电脑跑小模型 | 本机 Ollama（`http://localhost:11434`），如 qwen2.5:0.5b/1.5b |
| 边缘 edge | 一台云服务器/实验室服务器 | 服务器上跑 Ollama 中型模型或轻量 FastAPI 边缘服务，HTTP 可达 |
| 云 cloud | 商用大模型 API | OpenAI 兼容 ChatCompletions（现有 `sdk_provider.py` 已支持火山 ARK） |

**设计原则**：三层统一抽象为"HTTP 可达的推理端点"，差别只在 base_url、模型规模与信任级别——这使 device/edge 可复用同一个适配器类，仅配置不同。

# R2 —— 端侧节点运行时（本地 Ollama 小模型）

## 开工前报告

**要做什么**：
1. 新建 `infrastructure/nodes/device/device_node.py`：`DeviceNode(NodeProfile)`，实现统一推理接口：
   ```python
   def infer(self, prompt: str, *, system: str = "", temperature: float = 0.7,
             max_tokens: int = 512, timeout_s: float = 30.0) -> InferenceResult
   def health(self) -> bool
   ```
   `InferenceResult` 定义于本轮（`infrastructure/nodes/descriptor.py` 同文件追加）：`ok/text/tier/model_id/latency_ms/usage/error/node_id` 七字段——这是贯穿 R4-R12 的统一返回契约。
2. 底层走 Ollama 原生 REST（`POST /api/generate`，流式关闭），用标准库 `urllib.request` 即可，**不引入新依赖**（符合 YAGNI 与 `12_TECH_STACK_SPEC.md` 依赖纪律）。
3. Ollama 未启动时 `health()` 返回 False、`infer()` 返回 `ok=False` 并附错误原因——绝不抛异常打断主流程（为 R6 降级链路铺路）。
4. 测试：mock HTTP 层（注入 transport 或 monkeypatch），覆盖正常推理/超时/连接拒绝三类路径。

**对应比赛什么要求**：C-1 终端侧落地——"本地电脑小模型"就是赛题里的"终端异构算力"；隐私子任务不出本机的物理保证。

**和其它模块的联系**：
- 复用 R1 的 NodeProfile（base_url=http://localhost:11434, provider=ollama）；
- R6 派发器按 tier==device 寻址到本类；
- 与 `aegisos_agents/tools/llms/` 的关系：**不改 llms 层**（那是 Agent SDK 推理通路），DeviceNode 属于基础设施域的旁路推理通路，两者通过 R6 汇合，避免越界修改（遵守 `infrastructure/AGENT.md:24` 禁改 aegisos_agents 业务逻辑）。

**内部逻辑**：`infer()` = 组装 payload → urllib POST（带 timeout）→ 解析 `response`/`prompt_eval_count`/`eval_count` → 计算 latency_ms → 封装 InferenceResult。单次请求、无会话状态，天然幂等。

**验收标准**：`pytest tests/infrastructure/nodes/test_device_node.py` 全绿；本机装了 Ollama 时可用真机冒烟脚本打出真实小模型响应。
